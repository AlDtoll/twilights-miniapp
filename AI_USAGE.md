# Twilights Mini App — инструкция для ИИ-бота

## Что это

Telegram WebApp для мини-игр в ролевой игре Twilights.
URL: `https://loreworlds.ru:8443/`
Репо: `AlDtoll/twilights-miniapp`

Скрипт запуска: `twilights/minigames/send_miniapp.py` в репо `twilights-world`.

## Игры

### blackjack — игра в 21

Игрок набирает очки, стараясь не превысить 21. Навыки героя — модификаторы.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" blackjack \
  --thresholds "21:идеально|19-20:хорошо|15-18:норм|0-14:провал" \
  --modifiers "blade:Хлыст-клинок:+2|shadow:Тень:-1/+3"
```

Форматы модификаторов:
- `id:name:+N` — бонус
- `id:name:-N` — штраф
- `id:name:-N/+M` — выбор: штраф или бонус
- `id:name:foresight-suit` — подсмотреть масть следующей карты
- `id:name:foresight-value` — подсмотреть номинал
- `id:name:foresight-both` — подсмотреть полную карту
- `id:name:discard` — сбросить последнюю карту

Результат: `{"game":"blackjack","playerScore":19,"outcome":"хорошо","adjustedScore":21}`

### timing — остановить маркер в нужный момент

Маркер бегает по полосе (0–100%). Две отдельные кнопки: одноразовое замедление и фиксация результата.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" timing \
  --speed 1.5 \
  --thresholds "40-60:идеально|25-75:хорошо|10-90:норм|0-100:провал" \
  --slow-on-press
```

- `--speed` — скорость маркера (default 1.5; выше = сложнее)
- `--thresholds` — зоны в позициях 0–100 (по умолчанию центрированные)
- `--slow-on-press` — показать кнопку "Замедли" (одноразовая, 0.5 сек эффект на ~15% скорости)

**Две кнопки при `--slow-on-press`:**
- "⏱️ Замедли" — работает один раз, замедляет маркер на 0.5 сек
- "⚡ Стоп!" — фиксирует результат

Без `--slow-on-press` — только одна кнопка "⚡ Стоп!".

Результат: `{"game":"timing","position":47,"outcome":"идеально","level":3}`

### sequence — серия вопросов с таймером

Экран подготовки → общий таймер с прогресс-баром → вопросы по одному → итог.
Seed детерминирует порядок. Перезапуск недоступен.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" sequence \
  --prompt "<название испытания>" \
  --time 20 \
  --questions "<вопрос1>||<вопрос2>||<вопрос3>" \
  --thresholds "3:блестяще|2:хорошо|1:слабо|0:провал"
```

Формат вопросов: `текст:вар1,вар2,вар3:индекс_правильного`
Разделитель между вопросами: `||` (двойной пайп).
Индекс ответа: 0-based.

Примеры вопросов:
```
12÷4=?:2,3,4:1
Что лишнее?:меч,щит,сапог,арбалет:2
Столица Франции?:Берлин,Париж,Мадрид:1
```

`--thresholds` для sequence — пороги по **количеству правильных ответов** (не процент).

📚 Готовые банки вопросов (математика, травы, тактика, местность, магия, допрос — по сложности, с готовыми `--thresholds`): [`sequence/BANKS.md`](sequence/BANKS.md). Копируй набор прямо в `--questions`.

Результат: `{"game":"sequence","correct":3,"total":4,"outcome":"хорошо","level":2}`

### match3 — 3 в ряд (испытание воли/навыка)

Поле гемов. Игрок собирает линии 3+ за ограниченное число ходов. Каждый гем = 10 очков (3 в ряд = 30, 4 = 40, 5 = 50). Каскад: +10 за каждый уровень свыше первого.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" match3 \
  --moves 5 \
  --thresholds "230:идеально|200:успех|160:частичный|0:провал"
```

- `--moves` — число ходов (3 — короткое, среднее ~90; 5 — стандарт, среднее ~150).
- `--thresholds` — пороги по сумме очков.

Результат: `{"game":"match3","score":210,"outcome":"успех","level":2}`

### combat — боевая мини-игра

Система matching: у каждого врага каждый раунд **2 слота поражения** (🗡, оба видны сразу, у каждого своё требование) + **1 слот блока** (🛡). Игрок распределяет кубики по слотам — по одному кубу на слот.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" combat \
  --enemies 'Стражник:3:2|Лучник:2:1' \
  --player-hp 3 \
  --max-rounds 3 \
  --card-name "Финт" \
  --reroll-name "Мерцание"
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--enemies` | `Враг:3:1` | Враги `Имя:HP:danger[:defeat:block:attacks:special:special_req]`, через `\|`. **Базовый HP обычного врага — 3.** Максимум 4 врага. **Поле `danger` — метаданные для мастера (клиент его механически не читает).** Реальная опасность врага задаётся через HP, attacks, special, требования слотов |
| `--player-hp` | 3 | HP игрока (база 3; потолок 5 — выше клампится клиентом; бонусы поднимают) |
| `--max-rounds` | 3 | Лимит раундов — **не поражение** при истечении: `scene_revisit` (сигнал мастеру пересмотреть сцену) |
| `--slot-pool` | `1–6` | Пул значений для случайных точных требований, через запятую. `1,2,3,5,6` = без четвёрки |
| `--slot-types` | `exact` | Типы случайных требований: `exact,any,odd,even,gt,lt` через запятую. По умолчанию только точные |
| `--keep` | `type` | Поведение слотов между раундами: `always` (те же) · `type` (тот же тип, новое значение) · `random` (всё меняется) |
| `--card-name` | — | Включает стабильный модификатор ±1 (раз в раунд) с этим названием — «контрол» под особые преимущества |
| `--reroll-name` | — | Название переброса (раз в бой) |
| `--reroll` | false | Включить переброс без названия |
| `--abilities` | — | Способности героя через запятую, формат `имя[=N][:uses[:cooldown]]` (см. ниже) |
| `--support` | — | Обстрел/поддержка врага через `\|`: один куб атаки (1 урон), только блок (см. ниже) |
| `--counter` | — | Счётчик заряда `0/N` (задаёт N); наполняется → кубик-джокер (см. ниже) |
| `--dice-faces` | — | Кастомные грани 4 базовых кубов игрока (см. ниже) |
| `--round-time` | — | Лимит времени на раунд в секундах (по умолч. выкл) — для подстёгивания |

**Требования слотов** (что нужно от кубика, чтобы попасть). Задаются явно в `--enemies` (4-е поле = два слота поражения через запятую, 5-е = блок) или генерятся случайно из `--slot-types`/`--slot-pool`:
- число (`3`) — **точное**: ровно=2 урона/чистый блок, ±1=1, иначе 0/2 (единственный тип с нюансом ±1)
- `any` — любой куб · `odd`/`even` — нечёт/чёт · `>N` — выше N · `<N` — ниже N
- Для НЕ-точных типов попадание бинарно: условие выполнено = 2 урона / чистый блок, нет = 0 / полный урон.

Два слота поражения генерятся **разными**. Пример: `Ярмовец:3:1:odd,>4:even` — поражение по нечёт и >4, блок по чёт. `--slot-pool 1,2,3,5,6` — чтобы у слотов не выпадала четвёрка.

**Между раундами (`--keep`, по умолч. `type`):** `always` — слоты фиксированы на весь бой; `type` — тип сохраняется (число/чёт/нечёт/>/<), а значение меняется каждый раунд; `random` — тип и значение меняются каждый раунд. Применяется и к явным, и к случайным слотам (база берётся в раунде 1).

**Две атаки за раунд (опционально):** поле `attacks` или несколько блок-слотов → у врага столько слотов блока, сколько атак (каждый со своим требованием, по keep). Непрокрытая атака = 2 урона за каждую. Примеры: `Громила:4:1::even,odd` (2 атаки: блоки чёт/нечёт), `Громила:4:1::::2` (просто 2 случайных блока).

**Особенность врага (опционально, слот «✨», нейтрализуется кубом — по умолч. любым):** поле `special` + опц. `special_req` (требование куба для нейтрализации). Список пополняется. Сейчас:
- `dodge` / `dodge=0.2` — **Уклонение**: шанс (по умолч. 15%), что в этом раунде все удары игрока по врагу промахиваются. Поставь куб в слот «✨» → уклонение снято на раунд.
- `charge` — **Заряд**: если НЕ нейтрализовать в этом раунде, в следующий раунд враг бьёт две атаки (доп. слот блока). Нейтрализуешь — заряд сбит.
- Примеры: `Тень:3:1::::dodge=0.25`, `Таран:4:1::::charge:odd` (заряд, снять нечётным кубом).

**Способности героя (`--abilities`, опционально):** кнопки в зоне модов рядом с Движением. Каждая со своим бюджетом: `uses` — использований за бой (`0` = безлимит, по умолч. 1) и `cooldown` — раундов перезарядки между применениями (по умолч. 0). Формат токена `имя[=N][:uses[:cooldown]]`, токены через запятую. За ход можно жать несколько разных (в пределах их бюджета). Способности (target = нужен выбранный кубик):
- `extra_die` 🎲 **Доп. кубик** — добавляет 1 случайный куб в пул на этот раунд (без выбора кубика).
- `flip` 🔄 **Переворот** — выбранный куб → 7−значение (1↔6, 2↔5, 3↔4).
- `set=N` 🎯 **Грань N** — выбранный куб → N (задаётся в конфиге, не игроком; по умолч. 4).
- `split` ✂️ **Сплит** — выбранный куб V (≥2) → сам станет случайным v1, рядом появится новый куб v2, причём v1+v2=V.
- `save` 💾 **Сохранить** — выбранный куб откладывается: его значение переходит в следующий раунд (добавляется к новому броску).
- `merge` ➕ **Слить** — выбери первый куб → нажми «Слить» → выбери второй куб; оба заменяются одним (сумма, потолок 6).

Пример: `--abilities 'extra_die,flip,set=4:2:1,split,save,merge'` — у `set` грань 4; `extra_die` 2 раза с перезарядкой 1 раунд; остальные 1 раз за бой. (Переброс — отдельный флаг `--reroll`/`--reroll-name`, в способности не входит.)

**Обстрел / поддержка врага (`--support`, опционально):** сущности, которые «поддерживают» противника, но сами неуязвимы. У каждой — **один куб атаки (1 урон), который можно только блокировать** (бинарно: заблокировал → 0, не закрыл → 1). Нет HP, нет слотов поражения, нет особенностей. Формат `Имя[:block]` через `|`; `block` — требование куба блока (число/`any`/`odd`/`even`/`>N`/`<N`), пусто → случайное точное. Пример: `--support 'Лучник|Арбалет:even|Праща:>3'`.
- **Дальность лучников** делается через обычного врага с уклонением 100%: `dodge=1.0` — игрок каждый раунд тратит куб в слот «✨», чтобы «дотянуться» (нейтрализовать уклонение и попасть).

**Грань «джокер» 🃏:** вайлд — подходит под ЛЮБОЕ требование и даёт максимум (2 урона / чистый блок). В обычном броске не выпадает; появляется только через кастомные грани или кубик-джокер счётчика.

**Кастомные грани кубов (`--dice-faces`, опционально):** только для **4 базовых** кубов игрока (всё сверх — extra_die, кубик счётчика — обычные 1–6). Кубы через `|`, грани через `,`; грань = `1`–`6` или `joker`/`*`. Пустой набор для куба → стандартный 1–6. Пример: `--dice-faces '1,2,3|joker,6|4,5,6|*,*,1,2'` (2-й куб с джокером, 4-й — два джокера + 1 + 2).

**Счётчик заряда (`--counter N`, опционально):** шкала `0/N` (по умолч. при указании задаёт N, типично 3). Сохраняется между раундами. Наполняется на +1 двумя способами: (а) игрок **скидывает куб** в счётчик (куб уходит из пула), (б) **повергает не раненного** врага (полное HP на начало раунда) за один ход. Заполнен (`value=N`) → кнопка «🃏 Кубик-джокер»: добавляет в пул куб со всеми гранями-джокерами и обнуляет счётчик (выше N не копится). Пример: `--counter 3`.

**Экран готовности:** перед боем игрок видит экран с правилами и раскладом (противник, его силы, доступные инструменты героя, особое, лимит времени). Кнопка «В бой!» запускает первый раунд. Включён всегда.

**Лимит времени на раунд (`--round-time N`, опционально):** по умолчанию выкл. При указании — над раундом тикает таймер `⏱ N с`; за 3 секунды краснеет. Истёк → раунд разыгрывается **как есть** (что не распределил — непокрытые атаки нанесут урон). Для подстёгивания темпа. Пример: `--round-time 30`.

**🏃 Движение — карта по умолчанию (отдельно от ±1):** есть в каждом бою. Каждый раунд даёт ДВЕ кнопки со случайными дельтами −3..+3 (хаотично, «прыгают» каждый раунд, могут быть оба «+» или оба «−»); выбрав кубик, применяешь одну, 1 раз/раунд. Смысл — нужно попасть в нужное число, а не выжать максимум. Отключить: `gameData.movement=false`.
**±1 контрол** (`--card-name`) — стабильный, для отдельных преимуществ героя; не путать с Движением.

**Кубиков: 4 базово.** Чтобы повергнуть врага с 3 HP, нужно закрыть **оба** слота поражения (макс с одного куба — 2). Чистая оборона (только блоки, ни одной атаки, урона не получено; занимать ВСЕ кубы не обязательно) → **5 кубов** в следующем раунде (одноразово).

**⚠️ Сложность боя определяется механикой, не флагом.** Клиент combat **не читает** `--difficulty easy/medium/hard` (это метаданные для мастера в `build_contest.py`); поле `danger` в `--enemies` тоже не влияет на игру. Реальные рычаги сложности:

| Хочу сделать сложнее | Как задать |
|---|---|
| Долгий бой | Поднять `HP` в `--enemies` (обычный 3 → главарь 4–5) |
| Дополнительное давление | Добавить врагов (`--enemies A|B|C`, max 4) или обстрел (`--support 'Лучник|Копьё'`) |
| Труднее ударить главаря | `special=dodge=0.2..0.3` в `--enemies` — уклонение (нужен куб в слот ✨) |
| Заставить блокировать | `special=charge` + `attacks=2` — не нейтрализуешь заряд → 2 атаки в след. раунд |
| Сложное попадание | Явные слоты типа `>4`, `<3`, точные числа из узкого пула; `--slot-pool 1,3,5` — ограничить пул |
| Ограничить героя | Убрать movement (`gameData.movement=false`), не давать `--reroll`, `--card-name`, `--abilities` |

**HP людей-противников:** обычные бойцы — **3 HP** (default). Здоровые/крупные/живучие (главарь, здоровяк, ветеран) — **4 HP**. Выше 4 — редко и только для нелюдей/нежити/крупных тварей.

**Пример hard-боя с главарём:** `--enemies 'Грач:4:1:exact,>3:odd::dodge=0.25:any' --support 'Хравновец|Молодой:even'` (HP 4, точное+>3 для поражения, блок нечёт, уклонение 25%, плюс 2 обстрельщика).

**Особенности героя (Устрашающий взгляд и т.п.) — как реализовать:**
- **Не через `--special "текст"`** — это только нарратив, клиент игнорирует.
- **Снижение HP врага в `--enemies`**: `Грач:2:1` вместо 3 — «дрогнул, оценка ниже». Простой способ.
- **Через `--abilities`**: `flip:1:0` (раз за бой переворот куба), `set=6:1:0` (раз за бой куб на 6), `extra_die:1:0` (доп. куб раз за бой).
- **Через `--card-name "Устрашающий взгляд"`**: ±1 мод раз в раунд — если особенность более постоянная.

Результат (победа): `{"type":"combat","outcome":"victory","victory":true,...}`  
Результат (лимит раундов): `{"type":"combat","outcome":"scene_revisit","scene_revisit":true,"level":2,...}` — **не поражение**

**RPG-логика:**

| Навык героя | Что добавить |
|---|---|
| Боевой навык | `--card-name "Удар"` (±1 на атаку) |
| Магия / особенность | `--reroll-name "Мерцание"` (переброс) |
| Больше врагов | `--enemies '[...]'` с 3–4 объектами |
| Сложный бой | `--max-rounds 2` — урезать фокус-сцену, не «усложнить до поражения» |

### card — карточный бой (deck-builder)

Колода из карт оружия и магии; игрок разыгрывает карты против врага(ов) по ходам. Миньоны принимают удары вместо игрока, пока живы.

**Карты живут в пресете сеттинга, не в движке.** Движок card/index.html держит только словарь эффектов + схему карты и тянет карты по `fetch presets/<card_preset>.json`. Библиотека twilights (96 карт по 16 навыкам + стартовая колода) — в `twilights/minigames/presets/card/` (YAML-исходники), собирается в `card_preset.json` билд-скриптом. Как мастеру собрать новый кит — `twilights/minigames/presets/card/card_authoring.md`.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" card \
  --weapon-card sword_3 \
  --magic-card wizard_2 \
  --card-enemies '[{"name":"Страж","hp":100,"attack":40}]' \
  --player-minions '[{"name":"Тень","hp":50}]'
```

- `--weapon-card <id>` — карта оружия: `sword`/`axe`/`chain`/`dual`/`heavy`/`polearm`/`ranged` + `_1`…`_6` (напр. `sword_3`, `axe_6`). `_6` — ультимейт (стоит 2 энергии).
- `--magic-card <id>` — карта магии (`wizard_6`, `druid_2` и т.п.).
- `--cards "id|id|…"` — дополнительные карты в колоду.
- `--card-preset <name>` — какой пресет тянуть (движок → `presets/<name>.json`). Дефолт `twilights`; для card-игры проставляется автоматически.
- `--player-preset <run>/<player>` — частный пресет персонажа: читает `runs/<run>/<player>/presets/card.yaml` (loadout: weapon/magic/cards + опц. `custom[]` уникальные карты) и ставит их сам. Явные `--weapon-card`/`--magic-card`/`--cards`/`--card-preset` перекрывают пресет. Custom-карты вмешиваются в библиотеку на лету (без билда/деплоя пресета сеттинга), валидируются словарём эффектов. Схема/пример — `twilights/minigames/presets/card/card_authoring.md` § «Частный пресет персонажа».
- `--card-enemies '<json>'` — массив врагов `{name,hp,attack}` (новый формат); `--card-enemy` — один враг (устаревший).
- `--player-minions '<json>'` — союзники-миньоны.
- `--card-player-status '<json>'` — стартовые статусы героя (игрок начинает бой уже с ними, **без карт**). Ключи: `strength`/`dexterity`/`armor`/`block` (постоянные до расхода — броня/сила висят весь бой, блок обнулится в начале 2-го хода), `vulnerable`/`weak` (в ходах, затухают по 1/ход). Пример: `'{"armor":3,"strength":2,"vulnerable":2}'`. В движке видны теги 💪/🤸/🔩 и лог «Стартовые статусы: …».
- `--card-max-rounds N` / `--card-total-time SEC` / `--card-round-time SEC` — лимиты боя. **Дефолт для пресета twilights: 3 раунда, 60с на ход** (общего таймера нет); явные флаги перекрывают. Для других пресетов лимита по умолчанию нет. `max-rounds` — сколько ходов у игрока; `total-time` — общий таймер боя; `round-time` — таймер на один ход. **Исход по лимиту — НЕ поражение, а «Конец сцены»:** при исчерпании раундов или общего времени бой закрывается и итоги (HP героя/врагов, раунды) уходят мастеру нативно — мастер решает, что дальше (напр. новый раунд). `round-time` при обнулении просто авто-завершает ход игрока (враг ходит), сцену не закрывает. В движке видно панель `🔁 Раунд x/y · ⏱ общее · ⏳ ход`.
- `--card-base-count N` — сколько из 10 базовых карт замешать в стартовую колоду (`0` — без базовых; не задан — все 10). Меньше базовых = фокус-тест сигнатурного кита, нужные карты выпадают быстрее. В частном пресете персонажа то же задаётся полем `base_cards: N` в `loadout`. ⚠️ custom-карты в колоду не попадают автоматически — их id надо вписать в `loadout.cards` (в библиотеке они есть всегда, но в руку сами не приходят).

**Hex-шкала (ориентиры чисел).** HP человека — базовые **100** (атрибуты персонажа могут сдвигать). Атака врага **~40** (2–3 незаблокированных удара выносят из строя). Карты: лёгкая атака ~25, обычная сигнатурная ~40, ультимейт (`_6`, cost 2) ~44. Блок ~14–49, хил ~15–25. Статусы (уязвимость/слабость), draw, energy (3/ход) — без изменений. Миньон по умолчанию HP 50.

Словарь эффектов карты: `damage`, `block`, `heal` (числа); `vulnerable`, `weak`, `exhaust`, `all_enemies`, `lifesteal` (флаги true/false); `draw`, `energy` (числа); `strength` (+урон к каждой атаке, **может быть <0** — ослабление), `dexterity` (+щит к каждому block, тоже допускает <0), `armor` (постоянное снижение входящего урона после блока; клампится ≥0), `turns` (срок strength/dexterity в ходах; без него — весь бой; для armor игнорируется — броня постоянна). Карта может давать атаку+защиту+бафф разом. Щит игрока обнуляется в начале его хода, броня — нет. Схема карты: `id`, `name`, `skill`, `type ∈ {attack,defense,skill}`, `cost` (int≥0), `effect{}`, `rarity ∈ {common,rare}`, `description`, `flavor`.

**Эффект создания карт `add_cards`.** Карта, разыгрываясь, создаёт КОПИИ другой карты и кладёт их в колоду/руку/сброс — механика вроде «выковать оружие», «призвать», «зарядить». Значение — объект или массив объектов `{id, count, to}`:
- `id` (обяз.) — id карты-донора из библиотеки. Годится ЛЮБАЯ карта пресета сеттинга (`dual_1`, `sword_6`…) **и** любая `custom`-карта персонажа — движок ищет по общему CG_LIB.
- `count` (опц., дефолт 1) — сколько копий создать.
- `to` (опц., дефолт `deck`) — куда: `deck` (замешать в колоду в случайную позицию), `hand` (сразу в руку — сыграть в этот же ход, если есть энергия), `discard` (в сброс — придёт после перемешивания).
- Копии — полноценные карты (свой uid), играются как обычные. Донор в колоде БЫТЬ не обязан — карта берётся из библиотеки, поэтому так удобно «печатать» одноразовый расходник, которого в стартовой колоде нет.

Примеры:
- `effect: {add_cards: [{id: dual_1, count: 2, to: deck}], draw: 1}` — замешать 2× «Фарватер» в колоду и взять карту («Ковка клинков» Пало).
- `effect: {add_cards: {id: b_block, count: 1, to: hand}}` — дать в руку доп. «Блок» прямо сейчас.
- `effect: {damage: 10, add_cards: [{id: sword_1, to: discard}]}` — ударить и сунуть карту в сброс (комбо-заготовка на следующий цикл).

⚠️ `add_cards` кладёт в колоду карту, которой могло не быть в стартовом раскладе — это единственный способ ввести в бой карту, НЕ прописанную в `loadout.cards`. Если карта нужна в колоде с самого начала — её id всё равно надо вписать в `loadout.cards` (см. `--card-base-count`).

Результат: `{"game":"card","win":true,"outcome":"Победа","level":4,"turns":3,"player_hp_remaining":62,"enemies_defeated":2,"damage_taken":38}`

### hex — FFT-тактика на гексах (бой)

Пошаговый бой на поле **11×11**. Страница: `hex/index.html`. **FFT:** `--hex-hero` + враги (+ AP). **Legacy:** `--hex-player`. Боевая модель — ниже (armor-status + HP 60–160); changelog BB-HP 5–9 **не реализован**.

```bash
# FFT-режим: герой (оружие + опц. магия) против врагов
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" hex \
  --hex-hero '{"name":"Кай","weapon":"sword","magic":"wizard","emoji":"⚔️","hp":100}' \
  --hex-enemy '[{"type":"archer","name":"Лучник"},{"type":"shadow","name":"Тень"}]' \
  --max-rounds 5

# + спутники, террейн, стены (стены блокируют линию обзора)
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" hex \
  --hex-hero '{"name":"Кай","weapon":"axe","magic":"druid"}' \
  --hex-companions '[{"type":"cadaver","name":"Мертвяк"}]' \
  --hex-enemy '[{"type":"demonologist","name":"Колдун"}]' \
  --hex-terrain '{"rifts":1,"forests":2,"heights":1}' \
  --hex-walls '[[5,3],[5,4],[5,5]]'
```

Флаги:
- `--hex-hero` — JSON героя: `name`, `hp` (деф 100), `weapon`, `magic` (опц.), `emoji`, `atk`, `level`, `technique` / `techniques` (опц. приёмы).
  - `weapon`: sword, axe, ranged, heavy, dual, shield, unarmed, polearm, chain
  - `technique`: один id приёма (напр. `"sword_plastic"`) или `techniques`: массив id
  - опциональные приёмы (`technique` / `techniques`) — ровно 4, вешаются поверх базы независимо от оружия: `sword_plastic` (Пластичный удар: 40, 50% пробитие брони, +12 во фланге), `sword_lunge` (Выпад: сближение +45, сброс cd при ранении), `sword_smear` (Размазать клинок: заслон в силу стрелы, 30% второй слой, `mirroringOnUse`), `acro_vault` (Перепрыгнуть: прыжок 2 гекса через врага/препятствие, 1 👣 / 0 AP). Все cd 4.
  - `magic`: wizard, pyromancer, geomancer, aeromancer, aquamancer, druid, necro, demon, incenser, adept (`elementalist` — тип NPC, не magic героя)
- `--hex-enemy` — JSON-массив врагов `[{type, name, hp?}]`.
- `--hex-companions` — JSON-массив спутников игрока (те же типы юнитов).
  - типы юнитов: warrior, archer, cavalry, wizard, druid, incenser, demonologist, necromancer, adept, elementalist, shadow, cadaver
- `--hex-terrain` — JSON `{rifts, forests, heights}` (деф: 1 разлом, 1–2 леса, 1 высота). Вода/болото/обломки/кусты добавляются авто.
- `--hex-walls` — явные стены (блокируют LoS) `[[col,row],…]`. Герой стартует в col 0, враги в col 10.
- `--hex-player` — (legacy) старый список юнитов игрока; для FFT использовать `--hex-hero`.
- `--max-rounds` — лимит раундов (1 раунд = ход игрока + ход врага). **Default: 5**. **Не поражение** — сигнал мастеру пересмотреть сцену: что произошло вокруг, новые условия для следующей проверки. В результате: `scene_revisit: true`, `outcome: "Пересмотр сцены"`, без `win`.

Базовые приёмы по оружию (авто, зависят от `weapon`; урон / cd):
- **sword** ⚔️ — Удар (40, cd0), Быстрый удар (25, cd0, 50%→+1 AP)
- **axe** 🪓 — Рубящий удар (45, cd0), Вихрь (25 AoE·1, cd3), Раскол (50, cd2)
- **ranged** 🏹 — Выстрел (30, дальн.6), Прицельный (40, cd2), Прострел (35, cd3)
- **heavy** 🔨 — Дробящий (45, cd0), Волновой удар (30 AoE·wave, стан, cd3), Смерть молотом (60, cd4)
- **dual** ⚔️ — Двойной удар (40, cd0), Скользящий рывок (35, дальн.2, cd2), Вихрь клинков (25 AoE·1, cd3)
- **shield** 🛡️ — Удар щитом (35, cd0), Отбросить (25 + knockback, cd2), Заслон (барьер 35, cd3)
- **unarmed** 👊 — Серия ударов (35, cd0), Захват (20 + reposition, cd2), Зеркальный удар (60, cd4)
- **polearm** 🔱 — Копейный удар (35, дальн.2, cd0), Выпад (45, дальн.2, cd2), Тяжёлый замах (25 AoE·1, стан, cd3)
- **chain** ⛓️ — Хлыст (35, дальн.2, cd0), Зацеп и контроль (25 + pull, cd2), Волна кинетики (40 + стан, cd4)

Механика (как в коде):
- **AP** 4/ход (герой). Навыки **1–2 AP**. **Рывок** 💨: +2 move, щит 5, кд 1.
- **Move:** герой база 1 очко/ход; болото/мелководье/глубина ×2. **ZoC** + **атака вдогон** при уходе (не при `forcedMove`).
- **Hit:** melee 100%; ranged/magic — `accByDist`, −defense, −cover **или** −moved (max), clamp 35–95%.
- **Damage:** ability.damage (25–60) или atk-формулы; дальний falloff; высота +1, куст −1.
- **Mitigation:** shields → armor statuses (%×value, не изнашиваются) → HP (герой 60–160, люди ~100, тень 50, кадавр 85). `armorPenPct` на эффекте урона — частичное пробитие (не `ignoreArmor`).
- **Меч (база):** Удар (40, cd0), Быстрый удар (25, cd0, 50% +AP). **Приёмы** (опц., `--hex-hero` → `technique` / `techniques`): `sword_plastic`, `sword_lunge`, `sword_smear`.
- **Среднее мерцание (melee, cd>0):** 15% → полный сброс cd, затем половина max; цепочка сбрасывается при естественном откате. Условие: **HP-урон по врагу** (ранение; напр. Выпад, Пластичный) **или** `mirroringOnUse` (успешное применение без урона, напр. Размазать клинок).
- **AoE:** `aoe: N` + `aoeShape`: `radius` (деф.), `line`, `line_pair`, `wave` — направление от кастера к якорному гексу.
- **Displacement:** `knockback`/`pull` — 1 гекс; край карты — без эффекта; столкновение с юнитом/препятствием — 15 урона обоим, без сдвига, `vulnerable` (+10% к попаданию, 2 х.).
- **Reposition:** `effect:{type:'reposition'}` — сразу переместить цель на соседний к кастеру гекс (2 шага UI).
- **Jump:** опц. приём `acro_vault` (**Перепрыгнуть**): 2 гекса через врага/препятствие; **1 👣**, **0 AP**, cd 4; `mirroringOnUse` (15% перезарядка при успехе).
- **Spawn:** `effect:{type:'spawn_terrain', terrain:'crate'|'rock'|'shallow', duration?}` — `duration` опц.; без него — навсегда.
- **DoT:** `poison`/`bleed` на юните — тик в **начале** хода цели; отдельные статусы, без стака/refresh; иконки 🧪/🩸.
- **Прочие эффекты:** stun, ignite (трава), summon, heal, debuff atk, chain, barrier, dash.
- **LoS** для дальнего; **Тень** = полуголем (не призрак).

Результат (победа): `{"game":"hex","win":true,"outcome":"Победа",...}`  
Результат (лимит раундов): `{"game":"hex","scene_revisit":true,"outcome":"Пересмотр сцены","rounds":5,"max_rounds":5,"enemies_defeated":1,...}` — **без `win`**

### compare — что больше/тяжелее/дальше

Два объекта рядом. Игрок тапает тот, что больше (или что задал мастер). Несколько раундов на общее время.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" compare \
  --rounds '[{"pairs":[{"left":"Камень","right":"Перо","answer":"left"},{"left":"Мышь","right":"Кот","answer":"right"}],"timeLimit":15,"prompt":"Что тяжелее?"}]'
```

- `rounds` — массив с **одним** элементом-обёрткой. Внутри:
  - `pairs` — массив пар, каждая пара `{left, right, answer}`:
    - `left` / `right` — тексты кнопок.
    - `answer` — правильный вариант: `"left"` или `"right"`.
  - `timeLimit` — общее время на все пары (сек, по умолчанию 15).
  - `prompt` — вопрос-критерий (отображается над каждой парой).
- Клиент `compare/index.html` читает `gameData.pairs / timeLimit / prompt` с верхнего уровня. `send_miniapp.py` распаковывает поля из `rounds[0]` на верхний уровень для `compare` (аналогично `memory`/`findall`, коммит `f5401b2`).
- Флаг `--time N` (send_miniapp) тоже маппится в `timeLimit`, если он не задан внутри `rounds[0]`. Флаг `--prompt "…"` — то же самое.

⚠️ **Ограничение содержимого:** `left`/`right` должны быть **объективно сравнимыми фактами общего знания** (что тяжелее/легче/быстрее/крепче/больше/выше — «Камень vs Перо», «Мышь vs Кот», «Париж vs Мадрид»). Игрок должен уметь ответить, **не зная мастерской карты сцены**. Нельзя ставить сюжетные/скрытые вещи из адвенчур-драфта (места маршрута, ощущения от разлома, что «сильнее чувствуется») — игрок играет втёмную, это не проверка навыка, а угадайка.

Результат: `{"game":"compare","correct":4,"total":5,"timeSpent":9.2,"outcome":"Отлично","level":3}`

**Сложность (scene_modifiers → contest_catalog.yaml):** `--answer-time 3–15` сек/пару — больше = легче.

### sorting — расставь по порядку

Несколько элементов, нужно перетащить в правильном порядке (от начала к концу или как задаст мастер).

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" sorting \
  --rounds '[{"items":["Рассвет","Полдень","Закат","Ночь"],"prompt":"По времени суток"}]'
```

- `items` — элементы в правильном порядке (игрок видит их перемешанными). Форма: `["A","B",...]` **или** `[{"label":"...","value":N}]` (сортировка идёт по `value`; если задан только список строк — порядок берётся как есть).
- `order` — `"asc"` (по возрастанию value) или `"desc"`. По умолч. asc.
- `prompt` — критерий сортировки.
- ✅ **`--rounds` необязателен.** Без него клиент генерит 2–3 раунда с числами (asc/desc случайно) — пустым не запускается. Именованный контент задавай `--rounds`, чистую проверку скорости/внимания оставляй на автоген.

⚠️ **Ограничение содержимого:** `items` должны располагаться в **объективно очевидном порядке общего знания** (времена суток, месяцы, размер планет, ступени лестницы вкусов от сладкого к солёному, историческая хронология). Игрок должен уметь расставить их правильно, **не зная мастерской карты сцены**. Нельзя ставить сюжетные/скрытые последовательности из адвенчур-драфта (места маршрута по «нарастанию ощущения», порядок Теней у разлома) — игрок играет втёмную, это угадайка, а не проверка навыка.

Результат: `{"game":"sorting","correct":3,"total":4,"timeSpent":24,"outcome":"Хорошо","level":2}`

**Сложность (scene_modifiers → contest_catalog.yaml):** `--num-rounds 1–6` раундов — больше = сложнее; `--items-per-round 3–6` элементов — больше = сложнее.

### findall — найди все одинаковые

Поле символов — один вид целевой. Тапнуть все вхождения. Ошибка (лишний тап) = штраф.

**Клиент читает `gameData.grid` — готовый массив клеток.** Ключи `symbols`/`count` **не работают** — их нужно перевести в `grid` руками до отправки. `timeLimit` — внутри объекта rounds, не отдельным флагом `--time`.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" findall \
  --rounds '[{"target":"★","grid":["★","●","■","★","▲","♦","●","★","■","♦","★","▲","♦","★","●","■","★","▲","●","★","■","♦","▲","●","★","♦","■","▲","●","♦","▲","★","♦","■","●","▲"],"cols":6,"prompt":"Найди все звёзды","timeLimit":30}]'
```

- `target` — целевой символ.
- `grid` — **готовый массив** cols×rows клеток (пример: 6×6=36 клеток, 8 мишеней), уже перемешанный мастером.
- `cols` — число столбцов (rows = `len(grid) / cols`).
- `prompt` — заголовок «Найди …» над полем.
- `timeLimit` — лимит в секундах, внутри объекта rounds.
- `wrongPenalty` — `"time"` (штраф 3 сек) или `"point"` (штраф к счёту).
- ✅ **`--rounds` необязателен.** Без него клиент сам строит сетку 5×6 (30 клеток, случайный target + 3 дистрактора, 6–9 мишеней) — пустым не запускается. Именованную/тематическую сетку задавай `--rounds` с `grid`.

⚠️ **Ограничение содержимого:** `grid` — сетка символов для проверки внимания/различения, не сюжетная. `target` = **общеизвестный визуально выделяемый символ** (★ ● ■ ▲ ♦). Сюжетные ярлыки не рисуются — там только символ.

Результат: `{"game":"findall","effectiveFound":7,"total":8,"wrongTaps":1,"timeSpent":18,"outcome":"Отлично","level":3}`

**Сложность (scene_modifiers → contest_catalog.yaml):** `--time-penalty 1–10` сек штрафа — больше = сложнее.

### arkanoid — арканоид (выбей все блоки)

Классический арканоид на `<canvas>`: платформа внизу, мяч и ряды разрушаемых блоков. Игрок двигает платформу пальцем (тач) или мышью, тап по полю запускает мяч. Цель — разбить все блоки, не уронив мяч мимо платформы. Даётся 3 жизни.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "<текст>" arkanoid \
  --rows 5 --cols 7 --levels 1
```

- `rows` — число рядов блоков (1–8, по умолчанию 5).
- `cols` — число блоков в ряду (3–9, по умолчанию 7).
- `levels` — сколько уровней подряд (1–5, по умолчанию 1); каждый следующий добавляет ряд и ускоряет мяч.
- `prompt` — заголовок на стартовом экране.

Механика: верхние два ряда крепче (2 удара), остальные ломаются с одного. Угол отскока зависит от точки касания платформы. За разбитый блок +10×уровень очков, за частичное попадание +5, за пройденный уровень +50. Мяч мимо платформы — минус жизнь; ноль жизней — конец игры.

Результат: `{"game":"arkanoid","score":340,"stage":2,"win":true,"lives":2,"timeSpent":47,"outcome":"Победа!","level":3}`

- `score` — набранные очки, `stage` — достигнутый уровень, `win` — пройдены ли все уровни, `lives` — остаток жизней.
- `level` — тир результата (0–4): при победе зависит от остатка жизней, при поражении — от набранных очков.

- `--barrage-enemy` — JSON ОДНОГО босса сверху: `type` (shadow/warrior/archer/cadaver/demonologist/beast — задаёт темп ударов и окон), `name`, `hp`.

- `--barrage-aggression` — множитель темпа (деф 1.0; ≥1.5 — иногда два удара разом).

### rune-puzzle — сложи руну (слайдер-пазл, 15-puzzle)

Плитки руны перемешаны на сетке `size×size` — собрать исходный узор. Тап по плитке
→ тап по другой → они меняются местами (свободный обмен любых двух, не слайд).
Проверяет пространственное мышление/усидчивость. **Меньше ходов = выше исход**
(время — только жёсткий лимит: не успел → провал).

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "🧩 Сложи руну" rune-puzzle \
  --size 3 --time-limit 120 --shuffle 40 --rune-index 2 --prompt "Восстанови плетение руны."
```

- `--size 3|4|5` — размер сетки (по умолч. 3; лимит по умолч. 30/40/50 сек: +10 за размер).
- `--time-limit N` — лимит времени, сек (пол — 30). Время — только ограничитель, исход по ходам.
- `--shuffle N` — число ходов перемешивания (больше = сложнее).
- `--rune-index 0-7` — какой узор руны собирать.
- `--prompt "…"` — нарративный текст перед стартом.

Результат: `{"game":"rune-puzzle","size":N,"solved":true|false,"timeSeconds":N,"moves":N,"outcome":"…","level":0-6}`.

(оптимум ≈ 6 / 12 / 21 хода для 3×3 / 4×4 / 5×5):

| size | Идеально(6) | Отлично(5) | Хорошо(4) | Приемлемо(3) | Неудовл.(2) | Плохо(1) |
|------|----|----|----|----|----|----|
| 3×3 | ≤6 | ≤9 | ≤12 | ≤18 | ≤27 | >27 |
| 4×4 | ≤12 | ≤18 | ≤24 | ≤36 | ≤54 | >54 |
| 5×5 | ≤21 | ≤31 | ≤42 | ≤63 | ≤95 | >95 |

Не собрал за лимит времени → `solved:false`, «Провал», level 0.

### rune-dice — руны-кости (боевая, физика 2048-на-костях)

Физический бой на столе. Игрок **задаёт только направление** броска (сила фиксированная),
отпускает — на стол падает кость «1» (классика). Две одинаковые кости при касании
**сливаются** в кость номиналом +1; слитая кость слегка подтягивается к ближайшей паре
(магнит) → каскад. Каждое слияние бьёт по первому живому врагу. Когда броски раунда
кончились — враги отвечают (герой теряет сумму атак живых врагов), стол пересоздаётся,
раунд +1. Победа — все враги повержены; лимит раундов превышен → `scene_revisit`.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "🎲 Кости" rune-dice \
  --rd-hero '{"name":"Кай","hp":24}' \
  --rd-enemies '[{"name":"Страж","hp":70,"atk":4,"kind":"warrior"},{"name":"Тень","hp":45,"atk":3,"kind":"shadow"}]' \
  --rd-throws 5 --rd-start-dice 12 --rd-max-rounds 6 --prompt "Кости решают исход."
```

- `--rd-hero '{...}'` — JSON героя: `name`, `hp` (по умолч. 20), опц. `emoji`.
- `--rd-enemies '[...]'` — JSON-массив врагов: `name`, `hp`, `atk`, опц. `kind`. Бьются по очереди.
- `--rd-throws N` — бросков за раунд (по умолч. 5). Меньше = жёстче.
- `--rd-start-dice N` — сколько костей уже лежит на столе на старте (по умолч. 12).
- `--rd-max-rounds N` — лимит раундов (по умолч. 6). Превышение → `scene_revisit`.
- `--prompt "…"` — нарративный текст перед стартом.

Результат: `{"game":"rune-dice","outcome":"…","win":bool,"scene_revisit":bool,"level":0-4,"rounds":N,"max_rounds":N,"enemies_defeated":N,"enemies_total":N,"damage_dealt":N,"merges":N,"best_chain":N,"hero_hp_left":N,"hero_hp_max":N}`.
Победа: level по остатку HP героя (≥75%→4, ≥50%→3, ≥25%→2, иначе 1). Пересмотр сцены → level 2. Поражение → level 0.

Баланс-константы (в `rune-dice/index.html`, дефолты): сила броска `FIXED_SPEED=12`,
магнит слияния — сила `0.04`, дальность `SEEK_RANGE_R=5` (в радиусах кубика R=W/24),
`FRICTION=0.986`, отскок `DIE_REST=0.9`.

### rune-channel — поток руны (удерживать палец на бегущем огоньке)

### rune-forge — ковка руны (собрать из осколков, танграм-стиль)

Руна разбита на осколки-полимино. Осколки разбросаны в лотке снизу; игрок перетаскивает
каждый в контур руны сверху. Когда осколок ложится на своё место — **прикипает** (снап). Собрать
всю руну. Пространственное мышление. Осколки не поворачиваются (только перенос). Руны и разбиение
захардкожены и без наложений (проверено). Кнопки «Разбросать» / «Завершить» на экране.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "⚒ Выкуй руну" rune-forge \
  --rune-index 0 --size 3 --prompt "Осколки помнят форму — верни им её."
```

- `--rune-index 0-2` — какую руну ковать (по умолч. случайная; 0 ромб/4 оск., 1 крест/5 оск., 2 T-руна/3 оск.).
- `--size 3|4|5` — уровень подсказки: 3–4 контур руны виден, 5 — только рамка (сложнее).
- `--time-limit N` — лимит времени в секундах (0 = выкл; дефолт по --size: 3→55с, 4→70с, 5→90с). При истечении — принудительный финиш, грейдинг по уже уложенным осколкам.
- `--prompt "…"` — нарративный текст перед стартом.

Результат: `{"game":"rune-forge","rune":0-2,"difficulty":N,"shards":K,"placed":P,"fraction":0.0-1.0,"outcome":"…","level":0-6}`.
Исход по доле собранных осколков `placed/shards`: =1.0→6 (Руна выкована), ≥0.80→5, ≥0.60→4, ≥0.40→3, >0→2, была попытка→1, ничего→0.

### rune-lock — замок рун (вращать концентрические кольца, совместить узор)

Концентрические кольца из рунных секторов. Тап справа от центра — крутить кольцо по часовой,
слева — против. Кольцо выбирается по радиусу тапа. На сложности 4–5 кольца **сцеплены**: вращая
внешнее, тянешь и внутреннее (как шестерни) — сложнее выставить всё сразу. Замок открыт, когда
каждый радиальный луч — одного цвета, т.е. **все кольца имеют один и тот же сдвиг** (при любом
значении, не обязательно нулевом); центр загорается зелёным ✦.
Стартовая раскладка всегда несовместлена и всегда решаема (решать снаружи внутрь). Головоломка/логика.

```bash
python3 twilights/minigames/send_miniapp.py <chat_id> "◈ Открой замок" rune-lock \
  --size 3 --prompt "Кольца помнят верный узор — вспомни его и ты."
```

- `--size 3|4|5` — сложность: 3 — 3 кольца/6 секторов, не сцеплены; 4 — то же, сцеплены; 5 — 4 кольца/8 секторов, сцеплены.
- `--time-limit N` — лимит времени в секундах (0 = выкл; дефолт по --size: 3→45с, 4→60с, 5→80с). При истечении — принудительный финиш; обратный отсчёт виден в строке статуса.
- `--prompt "…"` — нарративный текст перед стартом.

Результат: `{"game":"rune-lock","difficulty":N,"rings":R,"slots":S,"aligned":A,"fraction":0.0-1.0,"moves":M,"outcome":"…","level":0-6}`.
`aligned` = размер наибольшей группы колец с одинаковым сдвигом (совмещение относительное, не привязано к нулю).
Исход по доле `aligned/rings`: все→6 (Замок открыт), ≥0.66→4, ≥0.34→3, иначе (были ходы)→2, без ходов→0.

## Общие параметры

⚠️ **Подпись ≠ критерий. Это ДВА РАЗНЫХ параметра — частая ошибка:**

| Параметр | Что это | Куда идёт |
|---|---|---|
| **3-й позиционный** `"<текст>"` | подпись сообщения (над кнопкой в чате) | только в Telegram-сообщение, **в игру НЕ попадает** |
| **`--prompt "<…>"`** | вопрос/критерий ВНУТРИ игры | в WebApp: compare рисует над раундом, sorting/estimate — заголовок |

Пример разницы (compare):
```bash
python3 twilights/minigames/send_miniapp.py <chat_id> \
  "Страж смотрит оценивающе" compare \        # ← подпись сообщения
  --prompt "Что дороже для стражника?" \       # ← критерий В ИГРЕ (над раундом)
  --rounds '[{"pairs":[{"left":"Меч","right":"Кошель","answer":"right"}]}]'
```
Если задать только `"<текст>"` без `--prompt` — игра покажет свой дефолт («Что больше?»), а не твой критерий. **Для compare/estimate `--prompt` обязателен.**

| Параметр | Игры | Описание |
|---|---|---|
| `--prompt` | compare, estimate, sorting… | Вопрос/критерий ВНУТРИ игры (не подпись!) |
| `--thresholds` | bj, timing, sequence, match3 | Пороги успеха |
| `--source-chat` | все | Куда добавить source_chat_id в результат (для мастера) |
| `--label` | все | Текст кнопки (иначе — автоматический) |

### Через build_contest.py

`build_contest.py` (каноничный путь: сам берёт пороги/ходы из каталога и выбирает игру случайно) разводит те же два параметра:
- `--caption "<…>"` → подпись сообщения (3-й позиционный send_miniapp);
- `--prompt "<…>"` → критерий ВНУТРИ игры (send_miniapp `--prompt`).

Если `--caption` не задан — подпись берётся из `--prompt`. Для compare/estimate всегда указывай `--prompt`.

## Как получить результат

После игры бот получает **обычное текстовое сообщение** с JSON в конце:

```
🎮 Игрок сделал выбор:
→ <описание>
{"game":"...","outcome":"..."}
```

Это стандартный polling — никаких специальных обработчиков не нужно.

**Важно:** WebApp-кнопки работают только в личных чатах с ботом.
Для групповой игры: кнопку слать в личку игрока (`user_id`), результат придёт туда же.
Чтобы результат шёл в группу — использовать `--source-chat <group_id>` и читать source_chat_id из результата.

## RPG-логика: как навыки → параметры

| Навык героя | Что добавить |
|---|---|
| Ловкость, рефлексы | timing `--slow-on-press`; reaction с коротким interval |
| Сила, боевой опыт | blackjack `+2` модификатор; combat с высоким HP врагов |
| Интеллект, образование | sequence — больше вопросов, меньше времени |
| Восприятие, внимание | findall или oddone |
| Память, сосредоточенность | memory — больше пар, меньше времени |
| Оценка и счёт | estimate — больше точек (до 20), меньше showTime |
| Предвидение, магия | blackjack `foresight-both` или `foresight-suit` |
| Удача | blackjack без модификаторов, пороги мягче |
| Организация, порядок | sorting — больше элементов, сложнее критерий |
| Сравнение и оценка | compare — больше раундов, меньше общее время |
